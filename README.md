# Когда можно шуметь в СНТ Татарстана

Автономная адаптивная памятка по Закону Республики Татарстан от 12.01.2010 № 3-ЗРТ. Интерфейс работает на русском и татарском языках, а главная страница показывает режим для текущей даты по московскому времени.

## Запуск

Откройте `index.html` в браузере или запустите любой статический сервер, например:

```sh
python3 -m http.server 8080
```

После этого страница будет доступна по адресу `http://localhost:8080`.

## Структура

- `index.html` — содержание и ссылки на нормативные документы;
- `styles.css` — адаптивный дизайн, анимации и версия для печати;
- `fonts/` — локальные WOFF2-файлы Golos Text и Noto Serif с лицензиями SIL OFL;
- `script.js` — языки, динамическая шапка, копирование и печать;
- `data/calendar.json` и `data/calendar-data.js` — сохранённый календарь для GitHub Pages и локального запуска;
- `scripts/update-calendar.mjs` — объединяет российский производственный календарь isDayOff и праздники Татарстана из Calendarific;
- `.github/workflows/update-calendar.yml` — обновляет календарь первого числа каждого месяца.
- `.github/workflows/deploy-pages.yml` — публикует статический сайт на GitHub Pages после изменений в `main`.

## Автоматическое обновление

API-ключ необязателен. Без него workflow всё равно обновляет федеральный производственный календарь через isDayOff, добавляет фиксированные праздники Татарстана и сохраняет уже известные региональные даты из предыдущей версии файла.

Чтобы дополнительно обновлять переходящие региональные праздники:

1. Создайте бесплатный API-ключ на Calendarific.
2. В репозитории GitHub откройте `Settings → Secrets and variables → Actions`.
3. Добавьте repository secret с именем `CALENDARIFIC_API_KEY`.
4. Запустите workflow «Обновить календарь Татарстана» вручную или дождитесь ежемесячного запуска.

Workflow получает текущий и следующий доступный год и сохраняет данные в репозиторий. Если Calendarific временно недоступен или ключ не настроен, обновление не падает и использует тот же безопасный fallback. Сам workflow не нужен для открытия сайта.

## Публикация на GitHub Pages

1. В репозитории откройте `Settings → Pages`.
2. В поле `Source` выберите `GitHub Actions`.
3. Отправьте изменения в ветку `main` или вручную запустите workflow «Опубликовать сайт на GitHub Pages».

Сайт не использует сервер и не обращается к календарным API из браузера. Шрифты, стили, скрипты и календарь загружаются из самого репозитория.

## Откат

Если публикацию нужно отменить, верните предыдущий коммит в `main`: workflow Pages автоматически опубликует восстановленную версию. Для отката только календаря восстановите из предыдущего коммита `data/calendar.json` и `data/calendar-data.js`, затем снова запустите публикацию.

Юридическая информация и ссылки проверены 15 августа 2026 года.
